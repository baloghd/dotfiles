# Worktrunk (wt)

All worktree operations go through `wt`. The branch name is the handle for everything: creating, listing, merging, removing.

## Rules

- **Never** run `git worktree add/remove` directly.
- **Never** use pi's native worktree features (`spawn.worktree`, `/spawn --worktree`, Agent tool `isolation: "worktree"`). They bypass wt's naming, hooks, and lifecycle.
- One worktree per task. Branch name = short task slug (e.g. `fix-auth-timeout`).

## Workflow

**Before spawning parallel work:** `wt list` to see existing worktrees/branches and pick a free name.

**Create:** `wt switch --create <branch>`

**Parallel agents:** launch each in its own worktree:

```sh
wt switch --create <branch> --execute 'pi "task prompt"'
```

Wrap in your usual background/dispatch execution so it runs fire-and-forget.

**Finish, local flow:** from the worktree, `wt merge` — commits with a generated message, squashes, rebases onto main, fast-forwards, removes the worktree and branch.

**Finish, PR flow:** `wt step commit` → `gh pr create` → `wt remove` after the PR merges.

**Cleanup sweep:** `wt list` to find stale worktrees, then `wt remove <branch>` for each.

## Useful extras

- `wt list --full` — CI status and AI branch summaries.
- `wt switch` with no args — interactive picker with diff/log previews.
- Commit messages and `wt list` summaries are generated by the `wt-llm` wrapper (pi headless); no manual `-m` needed for `wt step commit` / `wt merge`.
